Sempre que formos criar ou atualizar uma aplicação, SIGA ESTRITAMENTE as diretrizes de Qualidade e Padrões da Empresa definidos abaixo:

1. PALETA DE CORES E DESIGN (IDENTIDADE VISUAL HST):
   - Fundo Principal (bgDark): #111216 (Charcoal/Preto Profundo elegante)
   - Fundo Secundário/Cards (cardDark): #1A1D24
   - Texto Principal (textWhite): #F0F4F8
   - Texto Secundário (textGray): #A39C93
   - Cor Primária/Destaque (hstOrange): #E39B35 (Laranja/Ouro HST)
   - Cor Secundária (hstTaupe): #857A69 (Taupe/Bronze HST)

   - Bordas e Linhas: #252830

Utilize customização via QSS do Qt, "Glassmorphism" sutil, cantos arredondados (border-radius), sombras suaves de profundidade (Drop Shadows) e efeitos "hover" ou "glow" em todos os elementos clicáveis. Elementos visuais como gráficos e botões especiais devem ser desenhados na mão com QPainter para máxima fluidez.

2. ARQUITETURA DE CÓDIGO (C++ e Qt6):
   - Construa as interfaces gráficas **exclusivamente via código C++** (Não utilize arquivos .ui de arrastar e soltar do Qt Designer).
   - O código deve ser extremamente organizado e **ricamente comentado em português** para fins de estudo, separando visualmente os blocos lógicos (Componentes Base, Telas Específicas, Menu Lateral, Container Principal).
   - Use navegação moderna em página única (como o `QStackedWidget`) em conjunto com menus laterais elegantes para evitar múltiplas janelas abrindo e fechando (Estilo SPA web).

3. AUTOMAÇÃO DE BUILD:
   - Toda a estrutura deve utilizar `CMakeLists.txt` otimizado para Qt6.
   - Forneça (e mantenha) um script PowerShell (`rodar.ps1`) ou Bash na raiz do projeto que realize a limpeza completa do cache (pasta de build), chame o CMake, compile via MinGW/Ninja e já inicie o executável em tela. O desenvolvedor NÃO DEVE digitar comandos manuais de compilação repetidamente.

4. PADRÃO DO ARQUIVO README.md:
   - Todo projeto deve nascer acompanhado de um `README.md` instrucional e formatado.
   - O README deve conter obrigatoriamente as seguintes seções:
     a) Introdução e visão geral do projeto.
     b) Guia de Execução Local de Desenvolvimento (usando o script de automação).
     c) Guia passo a passo de Geração de Release de Produção (Explicando o uso da flag `-DCMAKE_BUILD_TYPE=Release`).
     d) Guia de Deploy e Distribuição, ensinando claramente como usar a ferramenta `windeployqt` no terminal do Qt para empacotar as DLLs e deixar o arquivo .exe pronto para rodar em qualquer máquina que não possua ambiente de desenvolvimento.
